# Джарвис — голосовой диспетчер терминалов Claude Code

Когда параллельно открыто пять-восемь терминалов Claude Code, каждый со своей задачей, переключаться между ними и читать хвосты становится отдельной работой. Джарвис снимает её голосом: нажимаешь клавишу, спрашиваешь «что по матану?» или «закинь в работу: проверь домашки», и через пару секунд в вырезе экрана появляется ответ или подтверждение, что задание ушло в нужный терминал.

```
FluidVoice (горячая клавиша, распознавание Parakeet на маке)
   │  POST /v1/chat/completions, модель dzharvis
   ▼
server.py  ── снимок всех терминалов (terminaly.py) ──►  постоянный claude -p (stream-json, Haiku)
   │                                                          │  SendMessage
   ◄──────────── короткий ответ в вырез экрана ───────────────┘  ▼
                                                         нужный терминал Claude Code
```

## Стек

Python 3 без внешних зависимостей (`http.server`, `subprocess`, `threading`), Claude Code CLI в режиме `--input-format stream-json`, FluidVoice как голосовой клиент с OpenAI-совместимым API. Озвучка ответов по желанию идёт через edge-tts.

## Как устроено

- `server.py` — OpenAI-совместимый сервер на `127.0.0.1:1236`. Он отдаёт одну модель `dzharvis`, а вместо языковой модели передаёт фразу постоянно запущенному процессу Claude Code.
- `terminaly.py` читает реестр сессий `~/.claude/sessions` и хвосты их журналов (последние 3 МБ, журналы весят сотни мегабайт) и собирает снимок: имя, статус, последнюю просьбу и последний ответ каждой сессии.
- `harakter.md` — короткий системный промпт диспетчера с правилами ответа, картой терминалов и переспросом перед необратимыми действиями.
- Процесс Claude живёт постоянно, фразы идут ему в stdin. Через 30 минут тишины или 15 фраз он перезапускается.
- Снимок приклеивается к каждой фразе, поэтому на вопрос диспетчер отвечает за один ход без вызова инструментов.
- Задания уходят в терминалы через `SendMessage`. Для режима репетитора отдельный «почтальон» пересылает вопрос в живую сессию и ловит ответ по метке в её журнале.
- FluidVoice обрывает запрос через 30 с, поэтому сервер ждёт 24 с, а дольше отдаёт «ещё смотрю» и присылает ответ уведомлением. Повтор того же запроса второй раз Claude не запускает.

Режимы переключаются голосом и флагом-файлом рядом с сервером:

| Режим | Что делает |
|---|---|
| диспетчер (по умолчанию) | отвечает о терминалах и раздаёт задания |
| `zashchita` (режим доклада) | ответы на вопросы по материалам своего доклада: отдельный Claude с материалами в системном промпте отвечает 1–2 фразами |
| `matan` | репетитор по заметкам подготовки к контрольной (`harakter-matan.md` и папка `DZHARVIS_MATAN`) |

Материалы режимов в репозиторий не входят, пути к ним задаются переменными из `.env.example`.

## Почему быстро

В первой версии на каждую фразу запускался `claude -p --resume` с полным системным промптом Claude Code, и диспетчер сам ходил за журналами инструментами: 10 с на «привет» и до 27 с на вопрос. После трёх изменений (постоянный процесс, короткий системный промпт и снимок в самой фразе) вопрос закрывается за 2,3–2,9 с, а отправка задания занимает около 4,7 с. Haiku отвечает на полсекунды быстрее Sonnet при тех же ответах.

## Запуск

```bash
python3 server.py                          # сервер на 127.0.0.1:1236
python3 server.py --sprosit "что по матану?"   # спросить без FluidVoice
python3 terminaly.py spisok                # живые сессии Claude Code
```

В FluidVoice нужно добавить своего провайдера (OpenAI-compatible) с адресом `http://127.0.0.1:1236/v1`, моделью `dzharvis` и пустым ключом и повесить на него режим команд. Для автозапуска подходит launchd-агент, который вызывает `zapusk.sh`.

Нужен установленный Claude Code CLI (`~/.local/bin/claude`).
